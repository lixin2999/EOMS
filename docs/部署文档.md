# EOMS 企业运营管理系统 · 部署与运维文档

> 适用版本：V1.2.8
> 部署方式：Docker Compose（生产推荐）
> 适用读者：运维工程师、DBA、系统管理员

---

## 0. 一键部署（Ubuntu 22.04 推荐）

目标：在全新 Ubuntu 22.04 服务器上一条命令完成 Docker 安装、密钥生成、镜像构建、服务启动与健康检查，并安装 `eoms` 运维命令。

### 0.1 前置条件

- Ubuntu 22.04 x86_64 / arm64，建议 4 核 8 GB 起；
- 已安装 `git`（或直接上传发布包解压到 `/opt/eoms`）；
- 可访问 Docker Hub 与配置的 PyPI/npm 依赖源（国内服务器建议加 `--cn-mirror`）；
- 服务器安全组/防火墙放行对外端口（默认 80）；
- 以 root 或具备 sudo 的账号执行。

### 0.2 执行部署

```bash
git clone <仓库地址> /opt/eoms
cd /opt/eoms
sudo bash deploy/install.sh
```

脚本执行流程：

1. 检测系统版本；
2. 安装 Docker Engine、Buildx、Compose v2，并启动 Docker；
3. 复制 `.env.docker.example` 为 `.env`，随机生成 `EOMS_SECRET_KEY`、`EOMS_AES_KEY`、PostgreSQL/MinIO/Grafana 密码，权限设为 `600`；
4. 根据访问地址自动设置 `EOMS_PUBLIC_ORIGIN`、`EOMS_TRUSTED_HOSTS`、`EOMS_COOKIE_SECURE`；
5. `docker compose build` 构建后端与前端镜像；
6. `docker compose up -d` 启动全部服务；
7. 轮询 `/healthz` 直到就绪；
8. 首次部署自动执行 `scripts/seed.py` 初始化演示数据（幂等）；
9. 安装 `/usr/local/bin/eoms` 运维命令。

### 0.3 常用参数

| 参数 | 说明 |
| --- | --- |
| `--port N` | Nginx 对外端口，默认 `80` |
| `--domain eoms.example.com` | 使用域名访问，生成 `http://域名[:端口]` |
| `--origin https://eoms.example.com` | 指定完整访问地址；HTTPS 时自动启用安全 Cookie |
| `--seed` | 强制初始化演示数据 |
| `--no-seed` | 不初始化演示数据 |
| `--minimal` | 不启动监控组件（Prometheus/Grafana/Loki/Promtail） |
| `--monitoring` | 启动监控组件（默认） |
| `--cn-mirror` | 使用阿里云 Docker 源，并配置 Docker 镜像加速与 pip/npm 国内源 |
| `--skip-docker-install` | 已安装 Docker 时跳过安装；与 `--cn-mirror` 同用时仍配置镜像加速 |
| `-h, --help` | 查看帮助 |

示例：

```bash
# 内网 8080 端口 + 国内加速
sudo bash deploy/install.sh --port 8080 --cn-mirror

# Docker 已安装：跳过安装，但仍配置镜像加速与国内依赖源
sudo bash deploy/install.sh --skip-docker-install --cn-mirror

# 云负载均衡已终止 TLS，EOMS 仅监听内网 8080
sudo bash deploy/install.sh --origin https://eoms.example.com --port 8080

# 轻量部署，不启用监控
sudo bash deploy/install.sh --minimal

# 空库初始化（已有 .env 时需显式指定）
eoms seed --yes
```

### 0.4 部署结果

部署成功后终端会输出访问地址、健康检查地址、配置文件位置与演示账号。常用命令：

```bash
eoms status                      # 容器与健康状态
eoms info                        # 访问地址与配置摘要
eoms logs                        # 跟踪 api/nginx 日志
eoms update                      # 备份 + 拉取代码 + 重建 + 滚动启动
eoms backup                      # 备份数据库与对象存储
eoms restore <归档>              # 恢复备份
eoms monitoring disable          # 关闭监控组件
eoms doctor                      # 环境诊断
eoms help                        # 全部命令
```

### 0.5 注意事项

- 脚本不会覆盖已有 `.env`，重复执行是安全的；但不会自动轮换密钥，避免数据库/MinIO 密码不一致。
- 若 `.env` 中仍含 `CHANGE_ME` 且数据库卷已存在，脚本会拒绝继续，需人工确认密码后再启动。
- 默认使用 HTTP 时自动设置 `EOMS_COOKIE_SECURE=false`，仅建议内网使用；公网请在 HTTPS 网关后使用 `--origin https://...` 部署。
- 首次部署默认写入演示数据，上线前必须修改 `admin` 密码并禁用不需要的演示账号；生产环境可加 `--no-seed` 并使用受控初始化脚本。
- 监控组件由 Compose profile `monitoring` 控制，`eoms monitoring enable|disable` 可随时切换。
- V1.2.3 起，`--skip-docker-install` 只跳过 Docker 安装；同时指定 `--cn-mirror` 时仍会配置 Docker 镜像加速。V1.2.4 起，已有 `/etc/docker/daemon.json` 会自动合并 `registry-mirrors`：保留其他配置与已有地址、自动去重、修改前备份，并在配置变化后重启 Docker。
- 若启动阶段出现 MinIO 服务镜像拉取超时，可重新执行 `sudo bash deploy/install.sh --skip-docker-install --cn-mirror`；已构建的业务镜像会复用缓存。
- `daemon.json` 合并失败时脚本会终止且不覆盖原文件；备份命名为 `/etc/docker/daemon.json.eoms-backup-时间戳`，可按终端输出路径人工恢复。
- V1.2.5 起，`--cn-mirror` 会显式拉取 MinIO 加速镜像，成功后写入 `.env` 的 `MINIO_IMAGE`；全部加速源失败时终止并提示人工配置完整镜像地址。
- V1.2.6 起固定使用 MinIO `RELEASE.2025-09-07T16-13-09Z`，优先尝试阿里云 FastGPT 缓存源、轩辕镜像，不再使用已失效的 `latest`。该历史版本上游已停止维护，生产环境应规划迁移到持续维护的 S3 兼容实现。
- V1.2.7 起，bucket 初始化、备份与恢复复用 `eoms-api` 镜像中的 Python MinIO SDK，不再拉取独立的 `minio/mc` 镜像；旧 `.env` 中的 `MINIO_MC_IMAGE` 不再生效。
- V1.2.8 起，部署前会检查 HTTP、Prometheus 与 Grafana 端口冲突。监控端口冲突时修改 `.env` 的 `PROMETHEUS_PORT`、`GRAFANA_PORT`，并同步 `GRAFANA_ROOT_URL`；不需要监控时可使用 `--minimal`。

## 1. 部署架构

### 1.1 组件拓扑

```
                 Internet / 内网
                        │
                  ┌─────▼─────┐
                  │  nginx    │  SPA 静态资源 + /api、/healthz、/readyz 反代
                  │  :80      │
                  └─────┬─────┘
                        │ Docker DNS（127.0.0.11）
          ┌─────────────┼─────────────┐
          │             │             │
     ┌────▼────┐   ┌────▼────┐   ┌────▼────┐
     │ api #1  │   │ api #2  │   │  ...    │  FastAPI / uvicorn，无状态可扩容
     └────┬────┘   └────┬────┘   └────┬────┘
          │             │             │
    ┌─────┴─────────────┴─────────────┴─────┐
    │  PostgreSQL 16   Redis 7   MinIO      │
    │  业务数据         缓存/锁/队列 对象存储  │
    └───────────────────┬───────────────────┘
                        │
     ┌──────────────────┴──────────────────┐
     │ worker（Celery）  beat（定时调度）     │
     └──────────────────┬──────────────────┘
                        │
     ┌──────────────────┴──────────────────┐
     │ Prometheus → Grafana；Promtail → Loki │
     └─────────────────────────────────────┘
```

### 1.2 服务清单

| 服务 | 镜像 | 对外端口 | 数据卷 | 说明 |
| --- | --- | --- | --- | --- |
| `nginx` | `eoms-web:1.0.0`（本地构建） | `${HTTP_PORT:-80}:80` | — | SPA、反向代理、安全响应头、32MB 上传限制 |
| `api` | `eoms-api:1.0.0`（本地构建） | 仅容器网络 `8000` | `eoms_storage:/app/.data` | FastAPI，默认 2 worker，启动时执行迁移 |
| `worker` | 同上 | — | 同上 | Celery worker，队列 `eoms`，并发 4 |
| `beat` | 同上 | — | 同上 | Celery beat，定时任务（单实例） |
| `db` | `postgres:16-alpine` | 不暴露 | `pgdata:/var/lib/postgresql/data` | PostgreSQL 16 |
| `redis` | `redis:7-alpine` | 不暴露 | `redisdata:/data` | AOF everysec |
| `minio` | `${MINIO_IMAGE:-minio/minio:RELEASE.2025-09-07T16-13-09Z}` | 不暴露 | `miniodata:/data` | 对象存储 |
| `minio-init` | `eoms-api:1.0.0`（复用） | — | — | 使用 Python MinIO SDK 初始化 bucket，执行后退出 |
| `prometheus` | `prom/prometheus:v2.55.1` | `127.0.0.1:${PROMETHEUS_PORT:-9090}` | `promdata` | 指标采集，保留 15 天（profile `monitoring`） |
| `grafana` | `grafana/grafana:11.4.0` | `127.0.0.1:${GRAFANA_PORT:-3000}` | `grafanadata` | 监控面板（profile `monitoring`） |
| `loki` | `grafana/loki:3.3.2` | 不暴露 | `lokidata` | 日志聚合，保留 7 天（profile `monitoring`） |
| `promtail` | `grafana/promtail:3.3.2` | — | 挂载 docker.sock | 采集容器日志推送 Loki（profile `monitoring`） |

> `db`、`redis`、`minio` 不映射宿主端口，仅容器网络内可达。Prometheus、Grafana 仅绑定 `127.0.0.1`，需通过 SSH 隧道或反向代理访问。

### 1.3 网络与卷

- 网络：`eoms-net`（bridge）。
- 数据卷：`pgdata`、`redisdata`、`miniodata`、`promdata`、`lokidata`、`grafanadata`、`eoms_storage`。
- `eoms_storage` 存放本地文件与 Celery beat 调度文件，迁移/备份时不要遗漏。

## 2. 环境准备

### 2.1 硬件建议

| 规模 | CPU | 内存 | 磁盘 | 说明 |
| --- | --- | --- | --- | --- |
| 试用/演示 | 2 vCPU | 4 GB | 40 GB | 单机全部服务 |
| 生产小型（≤100 用户） | 4 vCPU | 8 GB | 100 GB SSD | 建议 API 2 副本 |
| 生产中型（≤500 用户） | 8 vCPU | 16 GB | 300 GB SSD | 数据库独立或托管 |

磁盘需为 PostgreSQL、MinIO、Prometheus、Loki 预留增长空间；日志卷按 20MB × 5 个文件轮转。

### 2.2 软件要求

- Linux（推荐 Ubuntu 22.04 / Debian 12 / RHEL 9）；
- Docker Engine 24+；
- Docker Compose v2.20+；
- `tar`、`sha256sum`、`curl`；
- 可选：`git`（源码部署）、`mc`（对象存储运维）。

Windows / macOS 可用于开发验证，生产不建议使用 Docker Desktop。

### 2.3 网络与系统设置

- 开放入站端口：`80`（或自定义 `HTTP_PORT`）、`443`（启用 TLS 时）。
- 出站：SMTP（默认 465）、镜像仓库、时间同步。
- 配置 NTP，保证 JWT 过期判断、审计时间与定时任务准确。
- 设置时区 `Asia/Shanghai`（容器已内置 `TZ`）。
- 建议为 Docker 数据目录单独挂载数据盘。

### 2.4 检查命令

```bash
docker version
docker compose version
df -h
free -h
timedatectl
```

## 3. 配置

### 3.1 创建环境变量文件

```bash
cd /opt/eoms
cp .env.docker.example .env
chmod 600 .env
```

> `.env` 含密钥，禁止提交仓库、禁止写入镜像。生产建议使用 Docker secrets 或外部 KMS。

### 3.2 必填变量

| 变量 | 说明 | 生成方式 |
| --- | --- | --- |
| `POSTGRES_PASSWORD` | PostgreSQL 的 `eoms` 用户密码 | 强随机密码 |
| `MINIO_ROOT_PASSWORD` | MinIO 管理员密码 | 强随机密码 |
| `GRAFANA_ADMIN_PASSWORD` | Grafana 管理员密码 | 强随机密码 |
| `EOMS_SECRET_KEY` | JWT/会话签名密钥 | `python -c "import secrets; print(secrets.token_urlsafe(48))"` |
| `EOMS_AES_KEY` | 敏感字段 AES 密钥（32 字节 base64） | `python -c "import base64,os; print(base64.b64encode(os.urandom(32)).decode())"` |

未设置 `POSTGRES_PASSWORD`、`MINIO_ROOT_PASSWORD`、`GRAFANA_ADMIN_PASSWORD` 时，Compose 会因 `:?` 校验直接失败，这是预期行为。

### 3.3 运行环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `EOMS_ENV` | `prod` | `prod` 会关闭 `/docs`、`/redoc` |
| `EOMS_DEBUG` | `false` | 生产必须为 `false` |
| `EOMS_TIMEZONE` | `Asia/Shanghai` | 业务时区 |
| `EOMS_PUBLIC_ORIGIN` | `http://localhost` | 对外访问地址，用于 CORS |
| `EOMS_TRUSTED_HOSTS` | `*` | 生产建议改为实际域名 |
| `HTTP_PORT` | `80` | Nginx 映射端口 |
| `EOMS_RLS_ENABLED` | `true` | PostgreSQL 行级安全，SQLite 下无效 |

### 3.4 数据库与连接池

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `EOMS_DB_POOL_SIZE` | `20` | 每进程连接池大小 |
| `EOMS_DB_MAX_OVERFLOW` | `10` | 溢出连接数 |
| `EOMS_DB_POOL_TIMEOUT` | `10` | 获取连接超时（秒） |
| `EOMS_DB_STATEMENT_TIMEOUT_MS` | `15000` | SQL 语句超时（毫秒） |

> 数据库连接串由 Compose 自动拼接为 `postgresql+psycopg://eoms:${POSTGRES_PASSWORD}@db:5432/eoms`，无需在 `.env` 中重复配置。

### 3.5 认证与安全

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `EOMS_ACCESS_TOKEN_MINUTES` | `30` | Access Token（会话 Cookie）有效期 |
| `EOMS_REFRESH_TOKEN_DAYS` | `3` | Refresh Token 有效期 |
| `EOMS_COOKIE_SECURE` | `true`（prod） | 会话 Cookie 仅限 HTTPS 传输，生产必须为 `true` |

| `EOMS_LOGIN_MAX_FAIL` | `5` | 登录失败锁定阈值 |
| `EOMS_LOGIN_LOCK_MINUTES` | `15` | 锁定时长 |
| `EOMS_MAX_SESSIONS` | `3` | 单账号并发会话上限 |
| `EOMS_CAPTCHA_TTL` | `120` | 验证码有效期（秒） |
| `EOMS_PASSWORD_MIN_LENGTH` | `8` | 密码最小长度 |
| `EOMS_PASSWORD_EXPIRE_DAYS` | `90` | 密码有效期，`0` 表示不过期 |

### 3.6 文件与对象存储

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `MINIO_ROOT_USER` | `eoms` | MinIO 用户名 |
| `MINIO_BUCKET` | `eoms` | 业务 bucket |
| `EOMS_MAX_UPLOAD_MB` | `30` | 单文件上限；Nginx 固定 32MB |

| `EOMS_WORKFLOW_DUE_HOURS` | `24` | 审批节点默认时限 |
| `EOMS_WORKFLOW_LOCK_SECONDS` | `20` | 流程分布式锁时长 |
| `EOMS_BUDGET_ALERT_THRESHOLD` | `0.9` | 预算预警阈值 |
| `EOMS_RATE_LIMIT_PER_MINUTE` | `300` | 普通接口每分钟限流 |
| `EOMS_LOGIN_RATE_LIMIT_PER_MINUTE` | `10` | 登录接口限流 |
| `EOMS_FILES_RATE_LIMIT_PER_MINUTE` | `60` | 文件下载/预览独立限流桶 |
| `EOMS_IDEMPOTENCY_TTL` | `86400` | 幂等键保留时长（秒） |
| `EOMS_SMTP_HOST` / `PORT` / `USER` / `PASSWORD` / `FROM` / `SSL` | 空 / 465 / 空 / 空 / 空 / true | 邮件通知；留空则只发站内通知 |

### 3.8 可观测与初始化

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `PROMETHEUS_PORT` | `9090` | 仅绑定 `127.0.0.1` |
| `GRAFANA_PORT` | `3000` | 仅绑定 `127.0.0.1` |
| `GRAFANA_ADMIN_USER` | `admin` | Grafana 管理员 |
| `GRAFANA_ROOT_URL` | `http://localhost:3000` | Grafana 根地址 |
| `EOMS_SEED_ON_START` | `false` | 启动时初始化演示数据，仅首次使用 |

若 `9090` 或 `3000` 已被其他应用占用，可在 `.env` 中设置例如 `PROMETHEUS_PORT=19090`、`GRAFANA_PORT=13000`，并将 `GRAFANA_ROOT_URL` 改为 `http://localhost:13000`。安装脚本会在构建镜像前检查冲突并给出明确提示。

### 3.9 密钥轮换注意事项

| 密钥 | 轮换影响 | 建议 |
| --- | --- | --- |
| `EOMS_SECRET_KEY` | 全部 Access/Refresh Token 立即失效，用户需重新登录 | 可定期轮换，安排在低峰期 |
| `EOMS_AES_KEY` | 既有加密字段（手机号、证件号、银行账号等）将无法解密 | **不可随意轮换**；必须先完成存量数据解密/重加密 |
| `POSTGRES_PASSWORD` | 仅改 `.env` 不会修改数据库内密码 | 先在数据库中执行 `ALTER USER eoms WITH PASSWORD '...'`，再更新 `.env` 并重建容器 |
| `MINIO_ROOT_PASSWORD` | 重建 MinIO 后生效，历史数据不受影响 | 与备份脚本共用同一变量，需同步更新 |
| `GRAFANA_ADMIN_PASSWORD` | 重建 Grafana 后生效 | 建议同时启用 HTTPS 访问 |

## 4. 构建与启动

### 4.1 构建镜像

```bash
docker compose build
```

后端镜像多阶段构建（builder → runtime），运行用户为非 root（uid/gid 10001）；前端镜像 Node 构建后由 Nginx 运行。

后端 pip 安装遵循以下规则：

- pip 自身升级与项目依赖安装统一使用 `PIP_INDEX_URL`，默认 `https://pypi.org/simple`；
- 单次读取超时为 120 秒，失败自动重试 5 次；
- 启用 BuildKit pip 缓存，重复构建可复用已下载依赖；
- 国内服务器可使用 `--cn-mirror`，或在 `.env` 中手动设置 `PIP_INDEX_URL`。

若构建日志出现 `HTTPSConnectionPool(host='files.pythonhosted.org')` 或 `ReadTimeoutError`，先确认使用 V1.2.2 或更新版本的 `docker/Dockerfile`，再按网络环境重试：

```bash
# 国内服务器：写入国内 pip/npm 源并重新部署
sudo bash deploy/install.sh --skip-docker-install --cn-mirror

# 已手动配置 PIP_INDEX_URL：仅重建并更新后端服务
docker compose build api
docker compose up -d api worker beat
```

重试期间请检查 DNS、HTTP 代理与服务器出站策略；第三方镜像源持续不可用时，更换为可达的企业内部源。

### 4.2 启动

```bash
docker compose up -d
docker compose ps
```

启动顺序由健康检查控制：

1. `db`、`redis` 健康；
2. `minio-init` 创建 bucket 后退出；
3. `api` 等待数据库就绪 → 执行 `alembic upgrade head`（PostgreSQL 咨询锁 `728417` 串行化多副本迁移）→ 启动 uvicorn；
4. `nginx` 等待 `api` 健康后启动；
5. `worker`、`beat`、监控组件启动。

### 4.3 查看状态与日志

```bash
docker compose ps
docker compose logs -f api
docker compose logs -f worker beat
docker compose logs -f nginx
```

所有服务使用 `json-file` 日志驱动，单文件 20MB、保留 5 个。

### 4.4 访问

## 6. 反向代理与 HTTPS

### 6.1 默认 Nginx

`docker/nginx.conf` 已包含：

- SPA history fallback；
- `/api`、`/healthz`、`/readyz` 反向代理到 `api:8000`；
- Docker DNS `resolver 127.0.0.11` + 变量 `proxy_pass`，支持 API 副本重建；
- gzip、静态资源长缓存；
- CSP、`X-Content-Type-Options`、`X-Frame-Options`、Referrer-Policy；
- `client_max_body_size 32m`；
- `X-Trace-Id` 透传。

### 6.2 启用 TLS（二选一）

**方案 A：外部负载均衡/网关终止 TLS（推荐）**

- 由云 LB、Ingress 或独立 Nginx 处理 443；
- EOMS Nginx 仅监听内网 80，建议将 `HTTP_PORT` 改为 `127.0.0.1:8080:80` 或通过防火墙限制来源；
- 设置 `EOMS_PUBLIC_ORIGIN=https://eoms.example.com`；
- 设置 `EOMS_TRUSTED_HOSTS=eoms.example.com`；
- 确保代理传递 `X-Forwarded-Proto`、`X-Forwarded-For`、`X-Real-IP`。

**方案 B：EOMS Nginx 直接终止 TLS**

1. 准备证书 `fullchain.pem`、`privkey.pem`；
2. 取消 `docker/nginx.conf` 中 443 server 段注释，配置证书路径；
3. 在 `docker-compose.yml` 的 `nginx` 服务增加：
   - 端口 `443:443`；
   - 证书目录只读挂载，例如 `./certs:/etc/nginx/certs:ro`；
4. 重新构建并启动 `nginx`；
5. 将 80 端口重定向到 443；
6. 更新 `EOMS_PUBLIC_ORIGIN` 与 `GRAFANA_ROOT_URL`。

### 6.3 访问监控组件

Prometheus、Grafana 默认只绑定 `127.0.0.1`。远程访问建议 SSH 隧道：

```bash
ssh -L 9090:127.0.0.1:9090 -L 3000:127.0.0.1:3000 user@server
```

然后本地访问 `http://127.0.0.1:9090`、`http://127.0.0.1:3000`。不建议直接把 9090/3000 暴露到公网。

## 7. 扩缩容与高可用

### 7.1 扩容 API

```bash
docker compose up -d --scale api=3
```

- `api` 无状态、未设置固定 `container_name`，可水平扩容；
- Nginx 通过 Docker DNS 动态解析副本；
- 每个 API 容器默认 2 个 uvicorn worker，扩容后需同步评估数据库连接池总量；
- 迁移只由 `api` 执行，咨询锁保证多副本同时启动时串行执行。

### 7.2 数据库连接数估算

最大连接数 ≈ `api 副本数 × (DB_POOL_SIZE + DB_MAX_OVERFLOW) + worker 并发 + beat + 运维连接`。

例如 3 个 API 副本、默认池配置：`3 × 30 + 4 + 1 + 10 ≈ 105`，需确认 PostgreSQL `max_connections` 足够。

### 7.3 定时任务

- `beat` 必须单实例，不能扩容；
- `worker` 可按 `--scale worker=N` 扩容，任务通过 Redis 队列分发；
- 升级时先停 `beat`，避免重复调度。

### 7.4 已知限制

- Prometheus 使用静态抓取目标 `api:8000`，多副本时 Docker DNS 只会解析到其中一个 IP，指标不完整。生产多副本建议改用 DNS 服务发现或为每个副本单独配置抓取目标。
- MinIO、PostgreSQL、Redis 当前为单实例，生产高可用建议使用托管服务或集群方案。

## 8. 升级与回滚

### 8.1 升级前

1. 阅读 `release.md` 对应版本说明与变更内容；
2. 执行一次完整备份并校验 `.sha256`；
3. 确认磁盘空间充足；
4. 避开业务高峰与财务关账时点；
5. 记录当前镜像版本与 `alembic current`。

```bash
./scripts/backup.sh
docker compose images
docker compose exec api alembic current
```

### 8.2 升级步骤

```bash
# 1. 拉取或解压新版本代码
git pull            # 或覆盖发布包

# 2. 对比环境变量模板，补充新增变量
diff -u .env.docker.example .env

# 3. 构建新镜像
docker compose build

# 4. 滚动启动（迁移由 api 入口自动执行）
docker compose up -d

# 5. 验证
docker compose ps
curl -fsS http://127.0.0.1/readyz
docker compose exec api alembic current
docker compose logs --tail=100 api worker
```

> 若 `release.md` 标注了不兼容变更（如密钥、数据结构、接口），按该版本说明执行额外步骤。

### 8.2.1 V1.0.0 → V1.0.1 专项说明

1. 新增两个迁移，按修订顺序自动应用（`api` 入口的 `alembic upgrade head` 已包含，手工执行时保持同序）：
   - `a1f7c2d9e4b6`：建 `fin_pending_cost` 表、`fin_payment` 部分唯一索引 `uq_fin_payment_expense_active`，并在 PostgreSQL 下启用 RLS。
   - `b7e3d5a10c48`：建 `wf_instance` 部分唯一索引 `uq_wf_instance_biz_running`（仅约束 `status='RUNNING'`）。
2. 迁移前先排查存量冲突，否则迁移会失败：

   ```sql
   -- 重复的运行中流程实例
   SELECT company_id, biz_type, biz_id, count(*) FROM wf_instance
   WHERE status='RUNNING' GROUP BY 1,2,3 HAVING count(*) > 1;
   -- 同一报销单多条有效付款单
   SELECT expense_id, count(*) FROM fin_payment
   WHERE expense_id IS NOT NULL AND status IN ('PENDING','PAID')
   GROUP BY 1 HAVING count(*) > 1;
   ```

   有结果时先人工处理（关停多余流程实例 / 将重复付款单置 `CANCELED`）再升级。
3. 会话改为 HttpOnly Cookie：生产必须通过 HTTPS 访问并设置 `EOMS_COOKIE_SECURE=true`。
4. 反向代理必须透传 `X-Forwarded-Proto`（仓库内 `docker/nginx.conf` 已配置）；自建反代/云负载均衡若未透传，会导致安全 Cookie 不被浏览器回传，表现为登录成功后又立即掉线。
5. Cookie 模式下的写操作依赖双提交 CSRF：前端需能携带 `X-CSRF-Token` 请求头，CORS 已默认放行该请求头，自建网关不要剥离。
6. 仍有脚本或第三方系统使用 `Authorization: Bearer` 时不受影响（CSRF 仅对 Cookie 来源生效），建议后续逐步迁移。
7. 升级后确认 Beat 已包含新任务 `eoms.cost.post_pending`（默认每 10 分钟）：`docker compose logs beat | grep post_pending`，缺失时重启 `beat` 容器。

### 8.3 回滚

**应用回滚**

```bash
# 使用上一版本镜像标签重新启动（需保留旧镜像或重新构建旧版本）
docker compose down
docker compose up -d --no-build
```

建议每次发布为镜像打独立标签（如 `eoms-api:1.0.1`），不要长期复用 `latest`。

**数据库回滚**

- 优先使用 `alembic downgrade <revision>`，仅在迁移明确支持回退时使用；
- 涉及数据删除或结构重写的迁移，直接恢复升级前备份更安全；
- 恢复备份会丢失升级后产生的数据，必须在停机窗口内执行。

**完整回滚**

1. 停止 `api`、`worker`、`beat`；
2. 恢复数据库与 MinIO；
3. 切换回旧镜像；
4. 启动并验证。

## 9. 备份与恢复

### 9.1 备份内容

`scripts/backup.sh` 执行：

1. `pg_dump --format=custom` 导出 PostgreSQL；
2. 通过 `eoms-api` 镜像中的 `scripts/minio_storage.py` 备份 MinIO bucket；
3. 打包为 `backups/eoms-YYYYmmdd-HHMMSS.tar.gz`；
4. 生成 `.sha256`；
5. 删除超过保留期的旧备份（默认 30 天）。

### 9.2 执行备份

```bash
cd /opt/eoms
./scripts/backup.sh
```

自定义目录与保留天数：

```bash
EOMS_BACKUP_DIR=/data/backups EOMS_BACKUP_RETENTION_DAYS=60 ./scripts/backup.sh
```

依赖：`docker`、`docker compose`、`tar`、`sha256sum`（或 `shasum`）、MinIO 密码。

### 9.3 定时备份

```cron
30 2 * * * cd /opt/eoms && ./scripts/backup.sh >> /var/log/eoms-backup.log 2>&1
```

建议：

- 备份目录挂载独立磁盘；
- 每日备份后同步到异地/对象存储，遵循 3-2-1 原则；
- 每周校验 `.sha256`；
- 每季度做一次恢复演练。

### 9.4 恢复步骤

```bash
# 1. 校验并解包
cd /opt/eoms
sha256sum -c backups/eoms-20260101-023000.tar.gz.sha256
mkdir -p /tmp/eoms-restore
tar -xzf backups/eoms-20260101-023000.tar.gz -C /tmp/eoms-restore

# 2. 停止写入
docker compose stop api worker beat

# 3. 恢复数据库（覆盖同名对象）
docker compose exec -T db pg_restore -U eoms -d eoms --clean --if-exists --no-owner \
    < /tmp/eoms-restore/db.dump

# 4. 恢复对象存储
docker compose run --rm --no-deps \
    -e MINIO_ENDPOINT=minio:9000 \
    -e MINIO_ROOT_USER=eoms \
    -e MINIO_ROOT_PASSWORD='***' \
    -e MINIO_BUCKET=eoms \
    -v /tmp/eoms-restore/minio:/backup \
    --entrypoint /opt/venv/bin/python \
    minio-init /app/scripts/minio_storage.py restore /backup

# 5. 启动并验证
docker compose start api worker beat
curl -fsS http://127.0.0.1/readyz
```

### 9.5 备份指标

- 当前为每日逻辑备份，RPO ≈ 24 小时；
- RTO 取决于数据量、磁盘与恢复演练熟练度；
- 若要求更低 RPO，需增加 WAL 归档/流复制或使用云数据库自动备份。

## 12. 故障排查

### 12.1 快速定位

```bash
docker compose ps
docker compose logs --tail=200 api
docker compose logs --tail=200 nginx
docker compose exec api python -c "from app.core.config import settings; print(settings.env, settings.resolved_database_url)"
docker compose exec db pg_isready -U eoms -d eoms
docker compose exec redis redis-cli ping
```

### 12.2 常见问题

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| `api` 反复重启 | 数据库未就绪、迁移失败、密钥缺失 | 查看 `docker compose logs api`；确认 `POSTGRES_PASSWORD`、迁移日志 |
| `/readyz` 返回 503 | 数据库或 Redis 不可用 | 检查 `db`、`redis` 健康状态与连接数 |
| Nginx 502 | API 未启动或无健康实例 | `docker compose ps api`；查看 API 日志与健康检查 |
| 页面空白/404 | 静态资源未构建或路由回退异常 | 重新构建 `nginx`；确认 `web/dist` 生成 |
| 登录 401 循环 | 令牌失效、系统时间偏差、密钥变更 | 校时；清除浏览器存储；确认 `EOMS_SECRET_KEY` 未变 |
| 登录被锁定 | 连续失败 5 次 | 等待 15 分钟；或清理 Redis `login:fail:<username>` |
| 验证码不显示 | Redis 不可用或接口异常 | 检查 `/api/v1/auth/captcha` 与 Redis |
| 上传失败 | MinIO 未就绪、bucket 不存在、超过 32MB | 检查 `minio`、`minio-init` 日志与 `MINIO_BUCKET` |
| 启动时拉取 `minio/mc` 失败 | 使用 V1.2.6 或更早版本，或旧编排仍引用客户端镜像 | 升级到 V1.2.7；确认 `minio-init` 使用 `eoms-api:1.0.0` 与 `/app/scripts/minio_storage.py` |
| `address already in use` | HTTP、Prometheus 或 Grafana 端口被占用 | HTTP 使用 `--port N`；监控端口修改 `.env` 的 `PROMETHEUS_PORT`、`GRAFANA_PORT` 与 `GRAFANA_ROOT_URL`，或使用 `--minimal` |
| 异步任务不执行 | worker 未启动、Redis 队列异常 | `docker compose logs worker`；`celery inspect ping` |
| 定时任务重复/缺失 | beat 多实例或调度文件损坏 | 保证 beat 单实例；删除 `eoms_storage` 中 `celerybeat-schedule` 后重启 |
| 邮件不发送 | SMTP 未配置或网络不通 | 配置 `EOMS_SMTP_*`；检查 465 端口出站 |
| 报表数据为空 | 期间未关账、无计收/成本数据 | 确认数据与筛选期间；必要时生成报表快照 |
| 预算不预警 | 阈值配置或通知未生成 | 检查 `EOMS_BUDGET_ALERT_THRESHOLD`；查看通知与 worker 日志 |
| Grafana 无数据 | Prometheus 抓取失败 | 访问 Prometheus `/targets` 检查 `eoms-api` |
| 磁盘占用高 | 日志、备份、Prometheus/Loki 数据增长 | 清理旧备份；调整保留期；扩容磁盘 |
| 迁移卡住 | 咨询锁被占用 | 查询 `pg_locks`，确认是否有残留会话持有 `728417` |
| 时区错误 | 宿主机/容器时区不一致 | 统一 `TZ=Asia/Shanghai` 与 NTP |

### 12.3 数据库排查

```bash
# 连接数
docker compose exec db psql -U eoms -d eoms -c "select count(*) from pg_stat_activity;"

# 长事务
docker compose exec db psql -U eoms -d eoms -c \
  "select pid, now()-xact_start as duration, query from pg_stat_activity where state <> 'idle' order by duration desc limit 10;"

# 咨询锁
docker compose exec db psql -U eoms -d eoms -c \
  "select locktype, objid, pid, mode, granted from pg_locks where locktype='advisory';"

# 迁移版本
docker compose exec api alembic current
docker compose exec api alembic history | head
```

### 12.4 清理与重建（危险）

```bash
# 仅重启，不删数据
docker compose restart api worker beat

# 停止并保留数据卷
docker compose down

# 删除全部数据卷（不可恢复，务必先备份）
docker compose down -v
```
